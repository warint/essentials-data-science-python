Before the session

VS Codium, a local model, and then the straight line

1 · This one is longer than the others

This is the only pre-session that installs anything. Sessions 2 to 6 assume everything below is working, and none of them will ask you to install again.

The work, and roughly how long each part takes:

1 Install VS Codium 10 min
2 Install Python and make a virtual environment 30 min
3 Clone the course and run the verification suite 10 min
4 Install Ollama, pull Qwen 2.5 Coder, configure Continue 30 min
5 Read the assigned chapters 60 min
6 Work through the pandas section, at the keyboard 30 min
7 Read the inference section, and attempt the self-check 30 min

Budget three hours, once. Doing it in the ten minutes before class does not work, and every subsequent session depends on it. Steps 1 to 4 never have to be repeated.

2 · The toolchain, and why these four

1 VS Codium the editor — VS Code with the telemetry removed
2 Python 3.12+ in a virtual environment, one per project
3 Ollama + Qwen 2.5 Coder a language model running on your machine
4 Continue that model, inside the editor, beside the file

All four are open source, none requires an account or a subscription, and after setup none of them needs a network connection. That is not frugality — each choice teaches something the alternative would hide.

Why VS Codium rather than VS Code

Visual Studio Code is developed in the open under a permissive licence. The binary Microsoft distributes is not the same artefact: it adds telemetry and ships under a proprietary licence, and its extension marketplace is a Microsoft service with its own terms. VS Codium is the identical source, compiled without the telemetry and the branding.

The practical reason is the habit rather than this course’s data. The teaching data here is generated on your laptop and could not matter less. The habit is for the working file you will one day open under a non-disclosure agreement or a research ethics protocol. An editor that reports usage to a third party should be a decision you make once, deliberately — not a default you inherited.

Why a local model rather than a hosted one

The model you will install is Chinese, developed by Alibaba. It is worth being direct about that, because the reflex is to treat provenance as the security question, and here it is not.

Open weights, on your machine It cannot send your data anywhere. There is no connection to send it over — and you can verify that rather than trust it: turn the wifi off and watch it keep working.
A closed model behind an API Receives everything you type, by construction, wherever the company is domiciled.

On the dimension people actually care about — does my work leave this room — open weights running locally are the stronger guarantee, and the nationality of the developer does not enter into it.

And why a small one

Qwen 2.5 Coder is a vertical model: specialised for code, and consequently far better at code, for its size, than a general assistant many times larger.

  • A 3-billion-parameter model on a laptop is not competitive with a frontier system at open-ended reasoning.
  • At completing a pandas idiom, or explaining what a function does, it is entirely adequate.

Choosing a small specialised model over a large general one — and knowing which tasks admit that trade — is the applied judgement that separates a sensible AI deployment from an expensive one. It is also, almost exactly, the judgement session 4 makes about a deliberately biased estimator.

3 · Install VS Codium

Download from vscodium.com and install it as you would any application.

VS Codium uses the Open VSX registry rather than Microsoft’s Marketplace. Some extensions are missing from it. The two you need are both there.

Install these from the Extensions panel (Cmd/Ctrl + Shift + X):

  • Python — by Microsoft, on Open VSX as ms-python.python
  • Continue — the assistant panel, which part 7 points at a model

From here on, always use the VS Codium terminal — Ctrl + to open it. Not the macOS Terminal, not PowerShell. It starts inside your project folder and it sees your virtual environment.

A note on PATH that will save you an hour

A terminal reads your PATH once, when it opens. VS Codium reads it once, when it opens, and every terminal tab inherits that copy.

After installing To make it visible
A VS Codium extension Developer: Reload Window — Cmd/Ctrl + Shift + P
Python or git Quit VS Codium entirely and reopen it
Ollama A new terminal tab is usually enough — + in the terminal panel

“But I just installed it” is the single most common problem in this pre-session, and it is almost always this.

4 · Install Python

You want 3.12 or 3.13. Anything older than 3.10 will fail on syntax used throughout the course.

macOS — check what you have, then install if needed:

python3 --version
brew install python@3.12          # if Homebrew is installed

Windows — download the installer from python.org.

On Windows, tick “Add python.exe to PATH” on the first screen of the installer. If you miss it, python will not be a command your terminal knows, and the error message will not tell you why.

Linux — you already have it. python3 --version to confirm.

5 · Make a virtual environment

A virtual environment is a folder holding one project’s packages. It exists so that installing something for this course cannot break something else on your machine.

python3 -m venv .venv
source .venv/bin/activate          # macOS and Linux
.venv\Scripts\activate             # Windows

Your prompt now starts with (.venv). That is the whole signal that it worked.

You must activate it every time you open a new terminal. Ninety per cent of “it says the module is not installed” is a terminal where nobody ran activate.

6 · Get the course, and check it works

git clone https://github.com/warint/essentials-data-science-python.git
cd essentials-data-science-python
source .venv/bin/activate
pip install -r requirements.txt

Then run the suite that checks the course data is intact:

python scripts/verify_puzzles.py

You should see 39 lines beginning [ ok ] and, at the end, All planted answers are present and all traps still spring.

It takes about twenty seconds. If a line says FAIL, bring the output to class — that is a bug in the course, not in your setup.

What that suite just did

It generated all six course datasets and checked that each one still contains the answer it is supposed to contain.

Every dataset in this course is built on your machine from a fixed seed. Nothing is downloaded. Three things follow, and they shape how the sessions run:

  • The practice works with the wifi off.
  • Your numbers and your neighbour’s numbers are identical, so if you disagree, one of you has made an analytical mistake — which is the useful kind of argument.
  • There is a right answer, and you can check whether you found it.

7 · Install Ollama and pull the model

Install ollama.com, then, in the VS Codium terminal:

ollama --version
ollama pull qwen2.5-coder:3b

Check that it answers:

ollama run qwen2.5-coder:3b "In one sentence, what is a residual?"

Now turn your wifi off and run that again. It should still answer. That is the whole point of running it locally, and it is worth seeing once with your own eyes rather than taking on trust.

ollama: command not found immediately after installing? Open a new terminal. On Windows, quit VS Codium and reopen it — see the PATH slide.

Which size to pull

Start with the 3b. It is the one that works on a laptop without a dedicated graphics card, which is most laptops.

3b 7b
Disk 1.9 GB 4.7 GB
RAM while loaded ~3.4 GB ~8 GB
Needs a GPU no not required, but painful without 
ollama pull qwen2.5-coder:7b     # only if the 3b already runs on the GPU

Only try the 7b once ollama ps reports 100% GPU on the 3b. If it already says 100% CPU, the 7b is not a better model on your machine — it gives a comparable answer to the same question at roughly a quarter of the speed, and a tool slow enough to interrupt your thinking is a tool you stop using.

Whichever you pull, put that exact name in config.yaml. A name that is not installed produces a confusing error rather than a missing-model one.

Rule of thumb for any model: it needs its file size plus about a fifth in memory.

Check the context window

The model is sent your file. If its context window is small it silently drops the beginning and answers about the part it can still see — which looks like stupidity rather than truncation.

ollama run qwen2.5-coder:3b "hi"
ollama ps
NAME                SIZE      PROCESSOR    CONTEXT    UNTIL
qwen2.5-coder:3b    3.1 GB    100% GPU     32768      4 minutes from now

8192 or more — do nothing. 2048 or 4096 — raise it with /set parameter num_ctx 8192 inside ollama run, or via Ollama’s settings.

This differs by platform, so check rather than assume. The macOS app asks for a large window and the model caps it at its own maximum. On Windows the default is often 4096, which any real file will outgrow.

8 · Point Continue at it

Continue is installed but talks to nothing until it has a config file. The easiest way to open it is from inside Continue:

Open the Continue panel → the gear icon at its top right → Configure. It opens config.yaml in the editor, creating it if it does not exist.

Or from the terminal — the file lives in your home directory:

mkdir -p ~/.continue && open -e ~/.continue/config.yaml            # macOS
mkdir -p ~/.continue && ${EDITOR:-nano} ~/.continue/config.yaml    # Linux
New-Item -ItemType Directory -Force "$HOME\.continue" | Out-Null
notepad "$HOME\.continue\config.yaml"                              # Windows

What to put in it

name: essentials
version: 0.0.1
models:
  - name: Local coder
    provider: ollama
    model: qwen2.5-coder:3b     # the size you actually pulled
    roles: [chat, edit, apply]
context:
  - provider: file
  - provider: code
  - provider: diff
  - provider: terminal

Open a .py file, select a few lines, and press Cmd/Ctrl + L. If the panel answers, you are finished with setup for the whole term.

Put the model name you actually pulled in config.yaml. A name that is not installed produces a confusing error rather than a missing-model one.

Nothing at all? No model server is listening. Start Ollama — the app on macOS and Windows, sudo systemctl start ollama on Linux.

What the model is for, and what it is not

You will read far more code this term than you write: the session decks, the starter scripts, your own work from three weeks ago. A model beside the file answers “what does this do” without your leaving the file.

Good use Poor use
“Explain what this block does” “Write my analysis”
“Why does this throw a KeyError?” “Is this result significant?”
“What is the pandas idiom for this?” “Interpret this coefficient for me”

The standing rule of this course. Every deliverable must document at least one instance where you identified a model output as wrong, unverifiable or misleading, and explain how you established that. You are never penalised for using the model. You are penalised for using it uncritically.

The honest limitation, stated once: on a machine without a graphics card, a small model is a capable reader and an unreliable editor. It will explain a function correctly and then fail to produce a well-formed multi-file edit, because emitting a precise diff is a harder task than describing code. That is a fact about small models rather than about you.

9 · Enough pandas to start

Do this at the keyboard, not by reading. Activate the environment, then:

import essentials as ess

ess.catalog()                     # the six datasets, and what each one asks
d = ess.load("coasters")          # session 1's data

Now look at it. These five are the ones you will use constantly:

d.shape                           # (rows, columns)
d.head()                          # the first five rows
d.dtypes                          # what type each column is
d.describe()                      # count, mean, sd, quartiles, per column
d.columns.tolist()                # the names, as a list

Selecting and filtering

d["drop_m"]                       # one column, as a Series
d[["drop_m", "speed_kmh"]]        # two columns, as a DataFrame

d[d.drop_m > 100]                 # rows where the drop exceeds 100 m
d[d.propulsion == "gravity"]      # rows matching a string
d.query("drop_m > 100")           # the same filter, more readable

d["drop_m"] gives a Series; d[["drop_m"]] gives a one-column DataFrame. They print almost identically and behave differently. The double bracket means “a list of columns”, and the list happens to have one item in it.

Grouping, sorting, and new columns

d.groupby("propulsion")["speed_kmh"].mean()      # a mean per group
d.groupby("propulsion").size()                   # how many in each group

d.sort_values("speed_kmh", ascending=False).head(5)

d["speed_ms"] = d.speed_kmh / 3.6                # a new column

Before class, answer these three from the data, in Python: how many coasters are there · what is the mean top speed by propulsion · which single coaster has the largest drop_m.

10 · Enough inference to read a coefficient

A regression hands you three numbers per variable. You need to know what each one is before you can be told a fourth.

Coefficient how much \(y\) moves per one-unit move in \(x\) — in the units of \(y\)
Standard error how much that estimate would wobble if you collected the data again
\(t\)-statistic the coefficient divided by its standard error: how many wobbles from zero

A coefficient is a quantity with units. A \(t\)-statistic is a ratio, and has none. Reporting the second without the first is the most common way to say nothing at all.

The \(p\)-value, stated carefully

If the true effect were exactly zero, and I repeated this whole study many times, what fraction of those studies would produce a coefficient at least this far from zero?

That is the \(p\)-value. It is a statement about data under an assumption, not about the probability that the assumption is true.

It does not tell you the effect is large. It does not tell you the effect is real. With 2,000 rows, an effect too small to care about will clear \(p < 0.05\) comfortably — and you would still be right not to care.

What \(R^2\) is, and what it is not

\(R^2\) is the share of the variance in \(y\) that your fitted values reproduce. It runs from 0 to 1, and it rises whenever you add a variable — including a variable made of pure noise.

\(R^2\) measures how close the line is to the points. It says nothing about whether the line is the right shape.

Session 1’s puzzle is built precisely on that gap: a model with \(R^2 = 0.96\) that gets the answer wrong, sitting next to a model that gets it right. If you learn one thing before class, learn to distrust that number on its own.

12 · Self-check

On paper. If you cannot answer these, that is what the session is for.

  1. A regression of salary on years of experience gives a coefficient of 2,400. What are its units, and what does the number mean in a sentence?
  2. Two studies estimate the same effect. One reports \(p = 0.04\), the other \(p = 0.002\). What can you conclude about which effect is larger?
  3. You add a column of random numbers to a regression. What happens to \(R^2\), and why?

Answer 2 is the interesting one, and the answer is “nothing at all”.
